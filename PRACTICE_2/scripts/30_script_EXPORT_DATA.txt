-- COPY (SELECT * FROM v1) TO STDOUT WITH
-- (FORMAT csv, HEADER true, DELIMITER ',');

-- \o

--==============================
-- a different solution using the \COPY psql statement
-- Performs a frontend (client) copy. This is an operation that runs an SQL COPY command,
-- but instead of the server reading or writing the specified file,
-- psql reads or writes the file and routes the data between the server and the local file system.
-- This means that file accessibility and privileges are those of the local user, not the server,
-- and no SQL superuser privileges are required.
--
-- for detailed information see:
-- a01_postgresql-10-A4.pdf, or
-- https://www.postgresql.org/docs/current/app-psql.html
-- Note: For views, use \COPY (SELECT ...) TO format
--==============================
\COPY (SELECT * FROM v1) TO new_view_export.txt WITH (FORMAT csv, HEADER true, DELIMITER ',');

--==============================
-- Comments on the two approaches
--==============================
-- COPY: 
--   • Runs on the server side.
--   • Requires that the PostgreSQL server has access and permission to write to the given file path.
--   • Often requires superuser privileges.
--
-- \COPY:
--   • Runs on the client side (through psql).
--   • Uses the client’s local filesystem permissions, so no superuser rights are required.
--   • Easier to use in environments where the database server and the client machine are different.

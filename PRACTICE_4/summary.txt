# Exercício 7
Funções de funções e padrão decorator

a) u_function_of_function_and_decorator.py: Composição básica de funções
   - Funções aninhadas: f() retorna g() que retorna valor (conceito de closure)
   - Âmbito: Funções internas acedem a variáveis de funções externas
   - Função como valor de retorno: Demonstra funções como objetos de primeira classe
   - Simulação de classe: Função c(v) simula comportamento de classe com métodos acedidos via c()(1), c()(2)
   - Resultado: Compreensão de closures e conceitos de programação funcional em Python

b) Classe estendida com novos métodos (Exercício 7.b)
   - Método adicionado 3: Cálculo de cubo (y**3 + v)
   - Método adicionado 4: Cálculo de fatorial com acumulador
   - Método adicionado 5: Operação de concatenação de strings
   - Exemplos:
     * c_extended()(3)(5) = 125 (cubo de 5)
     * c_extended(10)(4)(4) = 34 (fatorial de 4 mais 10 = 24 + 10)
     * c_extended('Hello')(5)('World') = "Hello concatenated with World"
   - Resultado: Demonstra extensibilidade do padrão de "classe" baseada em funções

c) Conceito de meta-classe (Exercício 7.c)
   - Meta-classe: Função que retorna classes (função de ordem superior)
   - Três tipos de classe:
     1. "math": Operações (adição, multiplicação, subtração, divisão)
     2. "string": Operações de string (concatenação, maiúsculas, minúsculas)
     3. "geometry": Cálculos de área (círculo, retângulo, triângulo)
   - Uso: MathClass = meta_class("math") cria classe especializada
   - Exemplos:
     * MathClass(10)(1)(5) = 15 (adição: 10 + 5)
     * StringClass('Hello')(2)('World') = "HELLO | WORLD" (maiúsculas)
     * GeometryClass(5)(1)(None) = 78.54 (área do círculo com raio 5)
   - Resultado: Demonstra conceitos de meta-programação e padrão factory

d) Variações de decorator (Exercício 7.d)
   - Decorators f e g: Envolvem funções com "< >" e "# #" respetivamente
   - Sintaxe @f @g: Equivalente a h = f(g(h))
   - 8 variações testadas:
     1. @f @g → < # h # > (ordem original)
     2. @g @f → # < h > # (invertida)
     3. @f @f @f @g → < < < # h # > > > (múltiplos f)
     4. @g @g @g @f → # # # < h > # # # (múltiplos g)
     5. @f @g @f @g → < # < # h # > # > (alternada)
     6. @f → < h > (apenas f)
     7. @g → # h # (apenas g)
     8. @g @f @f @g @g → # < < # # h # # > > # (combinação personalizada)
   - Resultado: Compreensão da composição de decorators, a ordem importa (aplicação de baixo para cima)


# Exercício 8
Padrão de design Singleton usando decorators

Visão geral: x_singleton.py, z01_singleton_usage.py, z02_singleton_usage_anotherContext.py
- Padrão Singleton: Garante que apenas uma instância de uma classe existe em toda a aplicação
- Implementação: decorator @singleton usando closure para armazenar dicionário de instâncias

a) z01_singleton_usage.py: Uso básico de singleton
   - Duas classes singleton: C e D decoradas com @singleton
   - Comportamento:
     * c1 = C() cria instância, imprime "--> applying-the-decorator <--"
     * c1.f() imprime 1 (valor inicial)
     * c1.inc() incrementa para 2
     * c2 = C() retorna a MESMA instância que c1 (não cria novo objeto)
     * c2.f() imprime 2 (prova que é a mesma instância)
   - Mesmo padrão para classe D
   - Resultado: Múltiplas atribuições de variáveis (c1, c2) referenciam a mesma instância única

b) Momento de aplicação do decorator
   - Instrução print em x_singleton.py (linha 18): print("--> applying-the-decorator <--")
   - Momento: Decorator aplica-se UMA VEZ por classe quando a definição da classe é avaliada
   - NÃO é chamado quando instâncias são solicitadas (c1=C(), c2=C())
   - Saída mostra apenas 2 aplicações de decorator no total (uma vez para C, uma vez para D)
   - Resultado: Decorator envolve classe no momento da definição, não no momento da instanciação

c) z02_singleton_usage_anotherContext.py: Persistência de singleton entre módulos
   - Importa classes C e D de z01_singleton_usage
   - Sem novas aplicações de decorator (sem mensagens "--> applying-the-decorator <--")
   - Estado singleton persiste: Contador inicial é 2 (continuando do módulo anterior)
   - Múltiplos contextos testados:
     * Uso direto: c1=C() no âmbito do módulo
     * Âmbito de função: c=C() dentro da função f()
     * Contexto de classe: c=C() no __init__() e m() da classe H
     * Função main: c=C() em main()
   - Progressão do contador: 2→3→4→5→6→7 (todos acedendo à mesma instância)
   - Resultado: Padrão Singleton garante unicidade global em toda a aplicação, independentemente do contexto de importação ou âmbito

\section{Introdução}

Este laboratório tem como objetivo explorar métodos de avaliação de modelos de Machine Learning, combinando capacidades programáticas de Python com ferramentas de outras bibliotecas e do ambiente do Orange Data Mining.

Ao longo do trabalho, serão analisadas diversas técnicas de divisão de dados, métodos de amostragem, bootstrap, métricas de desempenho e construção de classificadores.

Os objetivos principais são:
\begin{enumerate}
    \item Integrar bibliotecas Python no ambiente Orange Data Mining
    \item Carregar e processar datasets para análise
    \item Compreender e implementar métodos de divisão treino-teste (holdout, stratified holdout, holdout repetido)
    \item Implementar e analisar métodos avançados de amostragem (leave-one-out, leave-p-out, k-fold, bootstrap)
    \item Construir classificadores utilizando scikit-learn
    \item Implementar múltiplas métricas de avaliação (exatidão, precisão, revocação, F1-score, Kappa de Cohen)
    \item Analisar avisos de métricas e compreender as suas causas
    \item Comparar desempenho em conjuntos de dados de diferentes tamanhos
\end{enumerate}

\begin{itemize}

    \item Particularmente importante para datasets desequilibrados

\section{Exercício 6: Construir um Classificador com Divisão Treino-Teste}

Isto permite-nos focar num único método de divisão e verificar a sua implementação corretamente.

\subsection{Método de Divisão Holdout}

O método holdout é a abordagem mais simples para divisão treino-teste. Divide o conjunto de dados numa única vez em dois subconjuntos:

\begin{itemize}
    \item \textbf{Conjunto de Treino:} Utilizado para treinar o modelo (tipicamente 60-80\% dos dados)
    \item \textbf{Conjunto de Teste:} Utilizado para avaliar o desempenho do modelo (tipicamente 20-40\% dos dados)
\end{itemize}

\subsubsection{Vantagens do Holdout}
\begin{itemize}
    \item Computacionalmente eficiente (apenas uma divisão)
    \item Simples de implementar e compreender
    \item Adequado para conjuntos de dados grandes
\end{itemize}

\subsubsection{Desvantagens do Holdout}
\begin{itemize}
    \item Alta variância nos resultados (dependente da divisão específica)
    \item Pode não ser representativo para conjuntos de dados pequenos
    \item Utiliza menos dados para treino em comparação com validação cruzada
\end{itemize}

\subsection{Implementação}

No código fornecido, o método holdout está configurado como:
\begin{lstlisting}
( "holdout", holdout, (1.0/3.0, 5) ),
\end{lstlisting}

Isto configura:
\begin{itemize}
    \item \textbf{Proporção de teste:} 1/3 (aproximadamente 33\%) dos dados para teste
    \item \textbf{Proporção de treino:} 2/3 (aproximadamente 67\%) dos dados para treino

\end{itemize}

\section{Exercício 7: Múltiplas Métricas e Divisões Repetidas}

\subsection{Objetivo}

O Exercício 7 expande o Exercício 6 ao:
\begin{enumerate}
    \item Completar a função \texttt{score\_recipe} para calcular previsões e pontuações
    \item Ativar múltiplas métricas de avaliação
    \item Implementar o método holdout repetido
    \item Lidar com avisos de métricas adequadamente
\end{enumerate}

\subsection{Completar a Função score\_recipe}

A função \texttt{score\_recipe} é responsável por:
\begin{enumerate}
    \item Gerar previsões utilizando o classificador treinado
    \item Calcular a métrica de pontuação especificada
\end{enumerate}

\subsubsection{Implementação}

As duas linhas principais adicionadas foram:

\begin{lstlisting}
y_predict = classifier.predict( X_test )  -- Gera previsoes para dados de teste
score = f_score( y_test, y_predict, **keyword_args_score )  -- Calcula a pontuacao
\end{lstlisting}

\textbf{Explicação linha por linha:}

\begin{enumerate}
    \item \texttt{y\_predict = classifier.predict(X\_test)}
    \begin{itemize}
        \item Utiliza o classificador treinado para fazer previsões no conjunto de teste
        \item \texttt{X\_test} contém os valores das características
        \item \texttt{y\_predict} conterá as etiquetas de classe previstas
    \end{itemize}
    
    \item \texttt{score = f\_score(y\_test, y\_predict, **keyword\_args\_score)}
    \begin{itemize}
        \item Compara as previsões com as verdadeiras etiquetas
        \item \texttt{f\_score} é uma função de métrica (exatidão, precisão, etc.)
        \item \texttt{**keyword\_args\_score} passa argumentos adicionais (como \texttt{zero\_division})
        \item Devolve um valor numérico representando o desempenho
    \end{itemize}
\end{enumerate}

\subsection{Métricas de Avaliação}

O Exercício 7 requer a ativação de cinco métricas de avaliação. Cada métrica fornece uma perspetiva diferente sobre o desempenho do classificador.

\subsubsection{1. Exatidão (Accuracy)}

\begin{equation}
\text{Accuracy} = \frac{TP + TN}{TP + TN + FP + FN}
\end{equation}

\textbf{Interpretação:} Proporção de previsões corretas em relação ao total de previsões.

\textbf{Quando usar:}
\begin{itemize}
    \item Conjuntos de dados equilibrados
    \item Quando todos os erros têm igual importância
\end{itemize}

\textbf{Limitações:}
\begin{itemize}
    \item Enganadora para conjuntos de dados desequilibrados
    \item Não distingue entre tipos de erros
\end{itemize}

\subsubsection{2. Precisão (Precision)}

\begin{equation}
\text{Precision} = \frac{TP}{TP + FP}
\end{equation}

\textbf{Interpretação:} Entre todas as previsões positivas, que proporção estava correta?

\textbf{Quando usar:}
\begin{itemize}
    \item Quando falsos positivos são dispendiosos
    \item Exemplo: deteção de spam (marcar incorretamente emails legítimos como spam)
\end{itemize}

\textbf{Características especiais:}
\begin{itemize}
    \item Indefinida quando não há previsões positivas (TP + FP = 0)
    \item Necessita do parâmetro \texttt{zero\_division} para lidar com este caso
\end{itemize}

\subsubsection{3. Revocação (Recall / Sensibilidade)}

\begin{equation}
\text{Recall} = \frac{TP}{TP + FN}
\end{equation}

\textbf{Interpretação:} Entre todos os casos realmente positivos, que proporção foi corretamente identificada?

\textbf{Quando usar:}
\begin{itemize}
    \item Quando falsos negativos são dispendiosos
    \item Exemplo: diagnóstico médico (falhar a deteção de uma doença)
\end{itemize}

\textbf{Características especiais:}
\begin{itemize}
    \item Indefinida quando não há amostras positivas verdadeiras (TP + FN = 0)
    \item Necessita do parâmetro \texttt{zero\_division} para lidar com este caso
\end{itemize}

\subsubsection{4. F1-Score}

\begin{equation}
\text{F1-score} = 2 \times \frac{\text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}} = \frac{2 \times TP}{2 \times TP + FP + FN}
\end{equation}

\textbf{Interpretação:} Média harmónica de precisão e revocação.

\textbf{Quando usar:}
\begin{itemize}
    \item Quando se necessita equilibrar precisão e revocação
    \item Conjuntos de dados desequilibrados
    \item Quando ambos falsos positivos e falsos negativos são importantes
\end{itemize}

\textbf{Características especiais:}
\begin{itemize}
    \item Herda problemas de divisão por zero tanto de precisão como de revocação
    \item Pode gerar avisos mesmo quando apenas uma das métricas principais tem problemas
\end{itemize}

\subsubsection{5. Kappa de Cohen}

\begin{equation}
\kappa = \frac{p_o - p_e}{1 - p_e}
\end{equation}

Onde:
\begin{itemize}
    \item $p_o$ = concordância observada (exatidão)
    \item $p_e$ = concordância esperada por acaso
\end{itemize}

\textbf{Interpretação:} Mede concordância considerando concordância por acaso.

\textbf{Valores de interpretação:}
\begin{itemize}
    \item $\kappa < 0$: Pior que acaso
    \item $\kappa = 0$: Concordância por acaso
    \item $0 < \kappa < 0.2$: Concordância ligeira
    \item $0.2 \leq \kappa < 0.4$: Concordância razoável
    \item $0.4 \leq \kappa < 0.6$: Concordância moderada
    \item $0.6 \leq \kappa < 0.8$: Concordância substancial
    \item $0.8 \leq \kappa \leq 1.0$: Concordância quase perfeita
\end{itemize}

\textbf{Vantagens:}
\begin{itemize}
    \item Considera concordância por acaso
    \item Útil para conjuntos de dados desequilibrados
    \item Fornece interpretação mais conservadora que exatidão
\end{itemize}

\subsection{Implementação das Métricas}

Cada métrica foi adicionada à lista \texttt{list\_score\_metric} com configuração específica:

\begin{lstlisting}
list_score_metric = [
    ("accuracy", accuracy_score, {}),
    ("precision", precision_score, {"zero_division": 0}),
    ("recall", recall_score, {"zero_division": 0}),
    ("f1_score", f1_score, {"zero_division": 0}),
    ("cohen_kappa", cohen_kappa_score, {})
]
\end{lstlisting}

\subsection{Holdout Repetido}

O método holdout repetido melhora a divisão holdout simples ao:
\begin{enumerate}
    \item Executar múltiplas divisões treino-teste com seeds aleatórios diferentes
    \item Calcular a média dos resultados em todas as repetições
    \item Fornecer estimativas mais estáveis do desempenho
\end{enumerate}

\subsubsection{Configuração}

\begin{lstlisting}
( "repeated_holdout", repeated_holdout, (1.0/3.0, 2, 5) ),
\end{lstlisting}

Parâmetros:
\begin{itemize}
    \item \textbf{Proporção de teste:} 1/3 (33\%)
    \item \textbf{Número de repetições:} 2
    \item \textbf{Seed inicial:} 5
\end{itemize}

\subsubsection{Vantagens sobre Holdout Simples}

\begin{itemize}
    \item Reduz variância nas estimativas de desempenho
    \item Fornece múltiplas avaliações para análise estatística
    \item Ainda computacionalmente eficiente em comparação com validação cruzada
    \item Melhor utilização de dados em comparação com holdout único
\end{itemize}

\subsection{Análise de Avisos}

Durante a execução do script com o conjunto de dados pequeno (\texttt{simple\_dataset} com apenas 6 instâncias), surgiram vários avisos. Compreender estes avisos é crucial para interpretação adequada das métricas.

\subsubsection{Tipos de Avisos}

\textbf{1. Aviso "Nenhuma Amostra Prevista"}

\begin{lstlisting}[language=bash]
UndefinedMetricWarning: Precision is ill-defined and being set to 0.0 
due to no predicted samples.
\end{lstlisting}

\textbf{Causa:} O classificador não previu nenhuma instância como positiva (TP + FP = 0)

\textbf{Impacto:}
\begin{itemize}
    \item Precisão torna-se indefinida matematicamente
    \item O parâmetro \texttt{zero\_division=0} define-a como 0.0
    \item Indica que o modelo pode estar enviesado para a classe negativa
\end{itemize}

\textbf{2. Aviso "Nenhuma Amostra Verdadeira"}

\begin{lstlisting}[language=bash]
UndefinedMetricWarning: Recall is ill-defined and being set to 0.0 
due to no true samples.
\end{lstlisting}

\textbf{Causa:} O conjunto de teste não contém nenhuma instância positiva verdadeira (TP + FN = 0)

\textbf{Impacto:}
\begin{itemize}
    \item Revocação torna-se indefinida matematicamente
    \item O parâmetro \texttt{zero\_division=0} define-a como 0.0
    \item Indica problema com tamanho do conjunto de dados ou estratificação
\end{itemize}

\textbf{3. Avisos de F1-Score}

O F1-score pode gerar avisos por duas razões:
\begin{enumerate}
    \item Herda avisos de precisão (sem amostras previstas)
    \item Herda avisos de revocação (sem amostras verdadeiras)
\end{enumerate}

Uma vez que o F1-score é calculado a partir de precisão e revocação, quaisquer problemas de divisão por zero em qualquer uma dessas métricas propagam-se para o F1-score.

\subsection{Parâmetro zero\_division}

O parâmetro \texttt{zero\_division} controla o que acontece quando ocorre divisão por zero no cálculo de métricas:

\textbf{Opções:}
\begin{itemize}
    \item \texttt{zero\_division=0}: Define a métrica como 0.0 (conservador)
    \item \texttt{zero\_division=1}: Define a métrica como 1.0 (otimista)
    \item \texttt{zero\_division="warn"}: Levanta aviso mas não define valor (padrão)
\end{itemize}

\textbf{Nossa escolha:} Utilizámos \texttt{zero\_division=0} porque:
\begin{itemize}
    \item Fornece interpretação conservadora
    \item Evita inflar artificialmente as pontuações
    \item Mantém coerência com a literatura de aprendizagem automática
    \item Fácil identificação de divisões de dados problemáticas
\end{itemize}

\subsection{Supressão de Avisos}

Para produzir saída mais limpa mantendo funcionalidade, adicionámos:

\begin{lstlisting}
from warnings import filterwarnings
from sklearn.exceptions import UndefinedMetricWarning

filterwarnings("ignore", category=UndefinedMetricWarning)
\end{lstlisting}

\textbf{Importante:} Embora suprimamos avisos visuais, os valores das métricas ainda são calculados corretamente utilizando \texttt{zero\_division=0}. A supressão é apenas para melhor legibilidade, não para esconder problemas.

\section{Boas Práticas e Conclusões}

\subsection{Principais Aprendizagens}

\begin{enumerate}
    \item \textbf{Tamanho do conjunto de dados importa:} Conjuntos de dados pequenos levam a métricas não fiáveis e avisos frequentes
    
    \item \textbf{Múltiplas métricas são essenciais:} Exatidão por si só pode ser enganadora; precisão, revocação e F1-score fornecem visão completa
    
    \item \textbf{Compreender os avisos:} Avisos de métricas indicam problemas de dados reais, não apenas questões técnicas
    
    \item \textbf{Uso adequado do zero\_division:} Define o comportamento para casos extremos de forma conservadora
    
    \item \textbf{Holdout repetido melhora a estabilidade:} Múltiplas repetições fornecem estimativas mais fiáveis
\end{enumerate}

\subsection{Recomendações}

\begin{enumerate}
    \item \textbf{Tamanho mínimo do conjunto de dados:}
    \begin{itemize}
        \item Para holdout: pelo menos 100 instâncias
        \item Para holdout repetido: pelo menos 50 instâncias
        \item Para conjuntos de dados mais pequenos: utilizar validação cruzada leave-one-out
    \end{itemize}
    
    \item \textbf{Utilizar divisão estratificada:}
    \begin{itemize}
        \item Garantir proporções de classes consistentes entre conjuntos de treino e teste
        \item Especialmente importante para conjuntos de dados desequilibrados
    \end{itemize}
    
    \item \textbf{Definir seeds aleatórios:}
    \begin{itemize}
        \item Garantir reprodutibilidade
        \item Facilitar depuração e comparação
    \end{itemize}
    
    \item \textbf{Monitorizar avisos de métricas:}
    \begin{itemize}
        \item Não ignorar simplesmente avisos sem compreensão
        \item Investigar causas de valores de métrica indefinidos
        \item Considerar se o tamanho do conjunto de dados é adequado
    \end{itemize}
    
    \item \textbf{Reportar múltiplas métricas:}
    \begin{itemize}
        \item Sempre reportar pelo menos exatidão, precisão e revocação
        \item Incluir Kappa de Cohen para conjuntos de dados desequilibrados
        \item Considerar métricas específicas do domínio quando apropriado
    \end{itemize}
\end{enumerate}
